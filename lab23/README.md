# Лабораторная работа 23

Парфёнок Иван Николаевич, группа 477. Node.js 22+, MongoDB 7+ с одним узлом replica set rs0. `npm ci`, заполнить .env по шаблону. Пользователь student имеет dbOwner на учебную базу и clusterMonitor для просмотра статуса rs0; пароль не публикуется.

Запуск заданий: `npm run task1` … `npm run task5`. Ошибка подключения: `npm run task1 -- --bad-uri`.

Для своей MongoDB: запустить mongod с `--replSet rs0 --bind_ip 127.0.0.1`, в mongosh выполнить `rs.initiate()`, затем настроить пользователя и авторизацию. Для replica set с авторизацией требуется keyFile. В проверке используется реальный mongod, запущенный mongodb-memory-server в отдельном локальном процессе.

Задание 3 создаёт миллион документов в отдельной коллекции big_data (повторные запуски идемпотентны). Сравнение полного чтения намеренно выполняется дочерним Node-процессом с ограничением heap 48 MiB; его реальная ошибка нехватки памяти демонстрирует риск toArray, основной процесс продолжает работу. Индекс сравнивается с полным сканированием через hint $natural. Не ожидайте заранее заданных времён: печатаются фактические измерения.

Задание 4 демонстрирует commit, abort, проверку отсутствия отменённой записи, insert/update/replace/delete Change Stream. На одном узле secondary отсутствует; secondaryPreferred читает primary.

API задания 5: /api/students (CRUD), /stats, /search?q=..., /batch; /api/metrics. WebSocket порт 3001, HTTP 3000. Кэш 60 секунд очищается при HTTP-изменениях и внешних событиях Change Stream. JSON Schema действует в БД, валидация также выполняется приложением. Ошибки 400/404/409. Остановка Ctrl+C закрывает сервер, stream, WebSocket и клиент MongoDB.
